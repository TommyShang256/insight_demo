# 当前方案：完整 JSON + 一个分层读取工具

## 保存层

保留 StatisticProfile 2.0 与 DimensionProfile 1.0 原始嵌套结构。全局统计、所有时间桶、所有单维值和已计算组合下的所有值及完整指标分布均写入 JSON。组合是否计算由 max_pairs 决定，未计算范围明确记录；不再按 Top-K 限制保存的组数。

SQL 已完成业务指标计算，profile 只描述结果行。时间/普通维度过滤已经执行，同维度 OR、跨维度 AND；不重新应用过滤，也不需要业务公式或辅助列。

## 读取层

profiling/reader.py 是唯一新增读取工具，只消费这两份 JSON：

- overview：全局分布、全量组大小/组间分布、时间概况及最多 24 个原代表桶。不能从桶分位数准确还原窗口分位数，所以不产生合并窗口统计。
- index：指定维度集合的值列表及行数/占比；未指定维度时列出指定范围的时间桶。
- detail：指定值或时间桶的已保存指标统计，可选择 metrics/fields。每个对象与指标组合形成一条表格行。

全局概况也分页；不把“没有在当前页展示”等同于“未参与计算”。全部组参与分布统计，但代表桶不保证发现全部时间现象。

## 呈现规则

工具最终返回 Markdown 表格和 total_count、returned_count、has_more、next_offset。默认最多 20 行、8192 UTF-8 字节；测量整个最终 JSON 信封（含换行），超限减少本页条数。单行过长明确要求进一步选择字段。长标签可在显示层截短并注明，原文件不修改。

没有数据库、持久化预算会话、签名游标或快照系统。分页用普通 offset，调用者保证文件不在分析途中变更；文件更新后从头读取。每次在内存解析 JSON，暂不引入索引或流式读取设施。

## 委派边界

主 agent 先读 overview，再按需要使用 index 定位切片、detail 核对分布。确定任务后将对应原 SQL 结果行交给 subagent；不能只给统计摘要就声称它已观察原始结果。

结果行占比分母为全部结果行，含 NULL。多个维度视角的任务会重叠，覆盖不能简单相加。源总体是否完整仍未知；不存在的时间桶不自动解释为缺失。没有存储的交叉切片不能凭现有摘要推算，工具会拒绝将维度组统计再次按时间筛选。

## 验证

原 16 项统计测试保留。新增 4 项验证全量保存 10,000 组/桶、受限 overview、完整分页、精确返回已存分布、NULL 选择、空结果和只读行为。共 20 项测试。
